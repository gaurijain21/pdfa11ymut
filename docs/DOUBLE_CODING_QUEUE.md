# Formal coding queue

This file documents the intended blinded-queue mechanism. It is not evidence that the recorded passes were independent human coders; the current repository retains role labels but no auditable coder identities or independent-human provenance.

The first-pass queue contains the 207 active formal validator-mutant reports. It was generated by `scripts/prepare_double_coding.py` from the hash-linked canonical ledger.

## Blinding and custody

`data/double_coding_queue.csv` contains opaque case IDs, report hashes, and blank coding fields. It intentionally omits the artifact ID, source golden, mutation operator, validator/configuration labels, and canonical classification. `data/double_coding_key.csv` is the steward/adjudicator key and must not be provided to either independent coder before both first-pass decisions are recorded.

When the queue is materialized, reports are copied to `evidence/double_coding/DC-####.<ext>` with opaque filenames. The copied bytes must match the hash in the queue. The raw evidence under the validator-specific directories remains the authoritative source.

## Coding procedure

1. Give Coder 1 and Coder 2 separate copies of the queue and the opaque evidence packet. They must not see each other's rows or the steward key.
2. Each coder records a decision for every case: `Detected`, `Missed`, `Needs Manual Check`, `Baseline Conflict`, `Outside Scope`, `Ambiguous`, or `Unrelated`.
3. Each coder records the relevant rule IDs/text and a short rationale. Manual prompts are not automated detections; baseline failures and unrelated/collateral findings are not intended kills.
4. The steward compares the two completed copies, fills `agreement`, and exposes the key only for disagreement review and adjudication.
5. The adjudicator records the final decision and rationale. Only then may the corresponding `coder_1`, `coder_2`, and `adjudication` fields in `data/validator_runs.csv` be populated.

Run `python scripts/merge_double_coding.py` to validate a completed queue without changing canonical data. Use `--apply` only after the validation succeeds and the steward has confirmed the packet is final. Apply mode writes the three legacy coder fields to `data/validator_runs.csv` and preserves the full rationales, rule references, and adjudication fields in `data/double_coding_decisions.csv`.

The preserved queue and decision ledger contain two separately recorded decision fields for all 207 cases and adjudication metadata. However, this repository retains role labels (`coder_1`, `coder_2`) rather than auditable human identities or a provenance record establishing that the passes were independent human coders. The paper therefore describes these fields as internal audit provenance and makes no independent-coder or agreement-statistic claim.
